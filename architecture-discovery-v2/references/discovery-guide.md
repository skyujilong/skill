# 架构发现指南

## 1. decisions.md 格式（check_arch_discovery.py 按此解析）

每个非「未命中」风险一个二级标题段，标题 `## RISK-N <简短标题>`，字段为 `- 键: 值`（中英文冒号均可，标签可带 `**` 等强调标记）：

```markdown
## RISK-3 事件重放是否幂等
- 结论: 消费端按 event_id 去重，重放安全，沿用现有实现
- 证据类型: code
- 证据: apps/api/src/events/consumer.ts:41-67
- 影响: SDD 无需新增去重规格；执行计划补一条重放测试
- 已回写: yes
```

- `证据类型` 只能是 `code` / `script` / `doc` / `user`。
- `证据`：code → `path:行号` 或 `path:起-止`；script → 命令 + 真实结果（不是只写命令）；doc → URL（并注明版本/日期）；user → 用户原话。
- `已回写: yes` 仅在 `resolve-risk` 成功后才写。可加任意额外要点（备选方案、遗留问题）。
- 不得用 TBD/TODO/待定/略/… 占位；不得出现上游 handoff 没有的 RISK 编号。未命中的风险不写段。

## 2. 证据类型

| 类型 | 适用 | 合格证据 | 常见不合格 |
| --- | --- | --- | --- |
| code | 现有行为、调用链、依赖方向 | 读过的 file:line；调用链工具结果要写出链路 | 只写文件名；凭记忆概括 |
| script | 框架/并发/时序行为不确定 | 最小可运行脚本 + 实际输出 | 只贴命令，没有输出 |
| doc | 外部 API、框架能力 | 当前版本官方文档 URL + 关键句 | 博客二手转述；未核版本 |
| user | 业务取舍、无法从代码得出的约束 | 用户明确确认的原话 | agent 替用户推断 |

## 3. 六类风险怎么验证

六类定义见 `req-align-v2/references/risk-patterns.md` §2（此处不复制）。验证侧重：

1. 数据流：追生产者→消费者的真实调用链，核对契约与 schema 变更的影响方（code）。
2. 时序/事件流：用最小脚本复现乱序/重放/丢失；框架自带能力先查文档（script / doc）。高危，方式由人选。
3. 跨服务/跨模块：画实际依赖方向，查循环与分层倒置（code）。高危，方式由人选。
4. 持久化与领域模型：对照 schema 与代码里同一术语的所有用法，确认含义唯一（code / user）。
5. 外部 API 契约：查当前版本文档，必要时跑一次最小请求（doc / script）。高危，方式由人选。
6. 可验证性：确认验收能转成断言；转不了就记录并回 req-align-v2 / sdd-v2，而不是在这里放过。

## 4. architecture.md

建议含二级标题：`## 分层与依赖方向`、`## 组件职责`、`## 技术选型与理由`、`## 关键约束`。检查器只对缺少含「分层」/「依赖」的标题、缺少含「选型」的标题发 WARN（不拦截）；其余两项纯属建议。
技术选型每项回答：业界标准解法是什么？框架是否已内置该能力？若不采用标准方案，理由是什么？默认采用标准方案，框架已有能力时不手搓替代。

## 5. flows-and-boundaries.md

建议含：`## 数据流`、`## 时序/事件`、`## 边界归属`（每个边界写明 owner，并提及相关 RISK-N）、`## 失败与幂等`；涉及多租户/权限时加 `## 多租户/权限边界`（范围由服务端上下文决定，不信任客户端传入）。检查器只在缺少含「数据流」/「时序」/「边界」任一的标题时发 WARN，并对未提及的待决 RISK-N 发 WARN。

## 6. 最小示例

```markdown
# decisions.md
## RISK-1 SSE 重连后事件是否重复
- 结论: 服务端带 Last-Event-ID 续传，客户端按 id 去重
- 证据类型: doc
- 证据: https://html.spec.whatwg.org/multipage/server-sent-events.html (Last-Event-ID 小节，2026-09 核对)
- 影响: 执行计划需实现 id 单调递增
- 已回写: yes

# architecture.md
## 分层与依赖方向
route → service → repository；web 只依赖 contracts。
## 技术选型与理由
SSE：标准方案；浏览器 EventSource 已内置重连，不自写。
## 关键约束
事件 id 单调递增。

# flows-and-boundaries.md
## 数据流
api 的 stream 模块 → 浏览器 EventSource。
## 边界归属
RISK-1 事件续传：owner 为 api 的 stream 模块。
## 失败与幂等
重连重放由客户端按 id 去重。
```

## 7. 何时可以不验证

- `未命中`：扫描时确无该类边界，无需决议段。
- 命中但可接受：仍需决议段，结论写「接受风险」，证据类型通常为 `user`（用户明确同意）并写明影响；不能静默跳过。
- 必须验证：时序/事件流、跨服务/跨模块、外部 API 契约，以及任何方案正确性依赖「我认为框架会这样」的情形。
- 证据取不到（无权限、环境缺失）：如实写入影响，让用户决定，不要编造证据。
